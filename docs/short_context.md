# Короткий контекст с восстановлением истории

В `coding.context_policy` доступны `bounded` (прежнее поведение, по умолчанию) и `single_action`. Второй режим сохраняет исходное задание, указания пользователя, план, краткие рабочие заметки, последнее наблюдение и актуальные условия завершения. Старые наблюдения и прочитанные исходники доступны через архив. Он работает в основном актёре, когнитивных ветках и простых read-only делегатах.

Основа — [You don’t need long context, arXiv:2611.05306](https://arxiv.org/abs/2611.05306), разделы 2.4 и 5: короткое состояние продолжения и выборочное чтение внешней памяти. Это адаптация SAC: сводка берётся из существующего поля `summary`, а результат инструмента добавляет runtime. Отдельного модельного вызова для сжатия после каждого действия нет. Сводка поэтому может отставать от последнего результата; результат имеет приоритет. Постобучение SSSM из обсуждения статьи здесь не реализовано.

```yaml
coding:
  context_policy: single_action
```

Режим отключает повторную отправку native-диалога, даже при `native_history: true`. Стабильная часть системного промпта остаётся прежней. Краткие заметки содержат оставшуюся работу, факты с указателями на доказательства, вопросы и следующий шаг. Они не заменяют проверку файлов или тестов. Настройка не меняет модель, лимиты, права инструментов или политику завершения.

## Поиск прошлых наблюдений

Перед подготовленным вызовом состояние сохраняется в `.sea/coding/<session>/context-archive/<actor>/<N>.json`. Архив есть в обоих режимах; приватные рассуждения провайдера он не сохраняет. Старые полные результаты инструментов остаются в существующих файлах `<id>.json`.

Инструмент **агента** `evidence` принимает ровно один селектор:

```json
{"query":"название функции", "after":0, "limit":5}
{"context_id":12, "start":1, "end":100}
{"id":"37", "start":1, "end":100}
```

Поиск буквальный и регистронезависимый: по состояниям своего актёра и полным результатам, на которые они ссылаются. `next_after` указывает на продолжение поиска. `complete: false` означает, что остались непросмотренные записи или возникли ошибки чтения. Нельзя подставить другого владельца или путь к файлу. Поиск архива изолирован по актёрам; прежний доступ по известному evidence ID остаётся механизмом явного обмена доказательствами между ветками.

Каждый результат архива помечен историческим. Старые указания пользователя не восстанавливают старые полномочия. Контрольные суммы обнаруживают повреждение состояния и изменение результатов, но не защищают от атакующего с доступом к самому хосту. Архив сохраняется при продолжении сессии. Это локальные данные проекта: они занимают место и могут содержать приватный текст задания, как остальные трассы сессии. Автоматического удаления истории нет.

## Сохранность условий и измерения

Полный текст задания больше не обрезается на 5000 символах. При укладывании в контекст защищены текущие указания, план, рабочая сводка, обязательства, вопросы пользователю и незавершённые операции. Если они не помещаются, запрос останавливается с явной ошибкой. Большие входные документы лучше хранить отдельными файлами и читать диапазонами; автоматически отличать документы от обязательных инструкций агент не пытается.

`context-usage.json` и `result.context_usage` содержат число подготовленных вызовов, сумму и максимум байтов пакета состояния, количество убранных старых наблюдений. Это **UTF-8-байты**, не токены и не счёт OpenRouter. Системный промпт, схема, повторные запросы и вызовы критика в эти числа не входят. Реальный запрос после адаптера виден в существующем `context_receipt.input_utf8_bytes`; токены и USD берутся из usage провайдера. Уменьшение пакета может потребовать дополнительных поисков, поэтому сравнивать нужно весь запуск.

## Проверка качества и цены

```sh
# Без модели и расходов: проверить план сравнения.
uv run python scripts/harness_search.py plan --config experiments/context_policy_pilot.json

# Платный запуск только при явном --live и рабочем OpenRouter.
uv run python scripts/harness_search.py run --live \
  --config experiments/context_policy_pilot.json \
  --output data/eval/context-policy-live
```

План сравнивает два режима на математике, алгоритмах и разработке: три повтора, разные семейства задач между screen/dev/test, максимум 45 выполнений и резерв $0.90 в общем лимите $1.00. Выбор фиксируется до test; продуктовые настройки автоматически не меняются. Пока новый режим не прошёл живое сравнение, `bounded` остаётся стандартом.

Офлайн-тесты проверяют восстановление выпавшего факта, настоящее исправление и запуск теста, новые указания во время генерации, продолжение сессии, изоляцию веток, повреждённый архив и сохранность ограничений. Они проверяют логику runtime; качество модели, экономия оплаченных токенов и результаты SWE-bench/Terminal-Bench ими не измеряются. Результаты сильных моделей из статьи нельзя автоматически переносить на модель 9–10B или на розничные тарифы API.

Проверка 5 ноября 2026: **1315 passed, 3 skipped**, сборка wheel успешна. На одинаковой сценарной траектории из 12 шагов с настоящим исправлением файла и тестом сумма пакетов состояния составила 145 365 байт для `bounded` и 103 630 для `single_action` (**−28.7%**); максимальный пакет — 14 942 и 9 755 байт. Решения задавались сценарием, модель не вызывалась. Локальные артефакты и воспроизводимый `replay.py` находятся в `data/eval/short-context-20261105/`. Живого сравнения качества пока нет.
