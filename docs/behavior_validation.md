## Какие проблемы обнаружили именно живые запуски

- **Потеря virtualenv в дочернем workspace.** Разрешение symlink превращало `.venv/bin/python` в системный Python, где не было pytest. Сохраняется путь интерпретатора virtualenv; регрессия проверяет настоящий импорт и `sys.prefix`.
- **Повторный вопрос после ответа пользователя.** Ответ учитывался при создании файла, но сохранённый вопрос оставался открытым. Теперь агент видит ID новых пользовательских сообщений и получает один ограниченный ход на связывание ответа перед финалом. Само наличие сообщения не считается ответом автоматически.
- **Лишние перепроверки после диагностики.** Read-only `run` ошибочно менял ревизию исходников. Теперь проверки устаревают после команд с правом записи в проект либо выполнения в отдельном изменяемом workspace. Реальная запись по-прежнему требует повторной проверки.
- **Нечем зарегистрировать проверку в режиме verify.** Для уже созданного результата без проверок доступен переход к implement с конкретным указанием зарегистрировать и выполнить проверку; ручной выбор режима сохраняет приоритет.
- **Входной файл принимался за недоставленный результат.** Контракт получил явные `inputs`, привязанные к именам из запроса и не пересекающиеся с выходными путями. Пропущенные реальные результаты по-прежнему отклоняются.
- **Неизвестный агенту Python окружения.** Локальный workspace сообщает точный интерпретатор с доступными библиотеками. Удалённому контейнеру путь хоста не передаётся.
- **Неинформативная остановка.** Если содержательный финальный ответ отсутствует, сообщение называет причину остановки и последнюю неудачную операцию, сохраняет возможность продолжения.

Отдельно исправлены ошибки самой оценки: разрешённый заданием запуск генератора сначала не получил тестовый confirmer; отказ песочницы был корректным. Проверка плана сначала требовала внутренний `plan`, хотя пользователь получил полноценный план текстом. Старые неудачные результаты сохранены. Во время ремонта была также обнаружена и исправлена опечатка с отсутствующим `import sys`; незавершённая попытка не засчитана успешной.

## Какая модель и какой профиль

Использован официальный авторизованный `codex exec` с моделью по умолчанию CLI; конкретный идентификатор модели в отчёте не установлен. CLI возвращал только структурированное следующее решение; исполнял инструменты **SEA**, не CLI. В журнале адаптер проверяет отсутствие собственных инструментальных действий CLI. Вход через существующий аккаунт пользователя, без извлечения токенов авторизации и без отдельного API-ключа.

Профиль оценки: adaptive planning, автоматический выбор домена, один основной агент (`max_nodes: 1`), тот же backend для актёра и финального критика. Дополнительные активные вызовы критика и отдельный decision backend выключены. До 12 ходов / 14 запросов на обычную задачу, до 16 / 18 для документов; общий предел одного запуска — 48 запросов и 1 млн токенов. Ограничения не были сняты ради завершения.

**Это не проверка текущего Flash-профиля, малой модели ≤10B, параллельных сабагентов или экономичности production-конфигурации.** OpenRouter не использовался после предыдущего HTTP 402; локальная модель и обучение не запускались. Обёртка Codex добавляет большой собственный контекст. Числа CLI отражают расход квоты аккаунта, а не известную стоимость в долларах (`cost_usd: null`). Сумма последних выбранных попыток — 47 вызовов / 918 751 токен; неудачные и прерванные попытки потребовали дополнительные ресурсы. Это не единый успешный прогон на одной неизменной версии кода.

## Как повторить и где доказательства

```sh
# Без --live запросов к модели нет.
uv run python scripts/codex_behavior_eval.py

# Использует существующий вход Codex и квоту аккаунта.
# Выбрать новый каталог: предыдущие попытки не перезаписываются.
uv run python scripts/codex_behavior_eval.py --live \
  --output data/eval/behavior-new-run

# Для точечного повторения:
uv run python scripts/codex_behavior_eval.py --live \
  --cases clarify_resume artifacts --output data/eval/behavior-targeted-run
```

`scripts/codex_behavior_eval.py` содержит задания, лимиты, независимые проверки, сохранение реальных решений и результатов инструментов. Автоматическое `passed` не заменяет отмеченную ручную проверку смысла и отображения документов. Тестовые проекты изолированы; ответ EUR и разрешение записи для генератора в этих проектах заданы явно.

Локальные доказательства не публикуются в Git:

- `data/eval/codex-behavior-fixed-20261101/` — код/инъекция, алгоритм, веб, план, а также ещё неуспешные уточнение и документы;
- `data/eval/codex-behavior-recheck-20261101/` — успешное уточнение после ремонта и обнаруженная ошибка контракта документов;
- `data/eval/codex-artifacts-verified-20261101/` — успешный документный сценарий, исходники и выходные файлы;
- `data/eval/prepush-20261101/` — сводный отчёт, ручная оценка плана, изображения PDF и журналы проверок;
- остальные каталоги `codex-behavior-*` / `codex-artifacts-*` сохраняют ранние, прерванные и неудачные попытки.
