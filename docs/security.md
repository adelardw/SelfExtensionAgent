# Защита агента и данных

Самоаудит работает локально, без LLM, оплаты API и загрузки модели. Он передаёт исходники как
данные отдельному процессу в OS sandbox: процесс разбирает AST, не импортирует код проекта,
не получает переменные окружения с ключами и не имеет доступа к сети. Если sandbox недоступен,
аудит сообщает об ошибке; запуска без изоляции нет.

```sh
.venv/bin/python -m src.security audit --network --output data/security/audit.json
# Или установленная команда:
sea security audit --network
```

Тот же аудит доступен агенту как `security_audit {}` и владельцу через `GET /security/audit`.
Модель получает компактный отчёт. Нельзя передать цель сканирования, произвольную команду,
исправление или обновление эталона. Пакеты не перехватываются: `--network` читает через `lsof`
метаданные сокетов текущего пользователя. Число открытых сокетов само по себе не доказывает взлом.
Это проверка по запросу; отдельный постоянно работающий сетевой IDS не запущен.

## Что блокируется кодом

- API проверяет Host, Origin и настоящий адрес клиента. Чужая веб-страница не должна управлять
  локальным агентом через браузер. Привязка к LAN без сильного токена запрещена; удалённые
  запросы требуют TLS. Заголовкам `X-Forwarded-*` сервер не доверяет.
- `browse`, `read_url`, `fetch_data` проверяют DNS до соединения, закрепляют выбранный публичный
  IP и проверяют каждый redirect. Localhost, внутренние адреса и cloud metadata блокируются.
  На произвольных страницах нет браузерного fallback, поэтому JS-only страницы могут не читаться.
- Известные ключи из окружения и некоторые типичные форматы секретов блокируются в web URL и
  поисковых запросах до DNS. Это эвристика: произвольные личные данные, разбиение или другое
  кодирование она надёжно не распознаёт. Для чувствительных проектов задайте точный список
  `AGENT_WEB_ALLOWED_HOSTS`; отсутствие списка разрешает публичные адреса.
- Внешние изображения в ответах превращаются в ссылки: браузер не скачивает их автоматически.
  CSP ограничивает скрипты, сетевые запросы и фреймы интерфейса.
- Файловые инструменты и OS sandbox команд защищают работающий `src`, frontend, конфигурацию
  запуска и `.sea` от перезаписи моделью. Генерация навыков не может менять эту область.
  Разработку самого агента ведите в отдельной копии; перенос в работающую установку — действие владельца.
- Вложения ограничены 32 MiB. Исполняемые бинарники, некоторые переименованные бинарники,
  неподдерживаемые типы, макросы/встроенные объекты Office и чрезмерно большие Office-архивы
  не принимаются. Исходный код допускается как текст. Gzip распаковывается с лимитом.
  Эти проверки не являются антивирусом; парсеры документов/медиа пока не перенесены в отдельную VM.

## Целостность и обновления

После проверки исходников владелец фиксирует текущие файлы:

```sh
sea security enroll
```

Эталон хранится в `.sea/security/integrity.json`. Повторная регистрация не перезаписывает его.
Перед API-запросами и вызовами основных инструментов проверяются хеши исходников, конфигурации
и собранного frontend. При расхождении операции блокируются до проверки владельцем.
Счётчики использования навыков исключены из хеширования; их флаги доверия и определения учитываются.
Для намеренного обновления: остановить сервер, проверить diff, собрать frontend, вручную
архивировать старый эталон и выполнить `enroll`, затем перезапустить сервер. Агенту такой
инструмент не предоставляется. Без первоначальной регистрации статус `unenrolled`: контроль
изменений ещё не активен. Эталон удостоверяет неизменность, а не безопасность самого кода.

События отказа пишутся в `.sea/security/events.jsonl` с ротацией около 1 MiB: время, поверхность,
код причины. URL, заголовки, ключи и тексты диалогов туда не записываются. Отчёт CLI сохраняется
с правами 0600. Это ограничения именно журнала безопасности: остальные журналы/траектории
имеют свои правила хранения и могут содержать пользовательский контекст.

## Границы доверия

Без `AGENT_API_TOKEN` локальные процессы пользователя всё ещё имеют доступ к API. Для защиты
от другого локального приложения задайте случайный токен из 32+ символов: API использует
`Authorization: Bearer …`, браузер — Basic с именем `sea` и токеном в качестве пароля.
Токен не передаётся параметром URL. Встроенный desktop WebView нужно отдельно проверить с
включённой аутентификацией; обход аутентификации для него не предусмотрен.

Облачная модель по назначению получает выбранный контекст. MCP, инструменты управления
браузером/устройством, подключения провайдера и фиксированные поисковые службы — отдельные
каналы, не закрытые общим HTTP-фильтром. Их отключают или изолируют отдельно для чувствительных
данных. Сейчас нет общего сетевого firewall, расшифровки TLS, проверки CVE-зависимостей или
гарантии распознавания любого prompt injection/вируса.

Код защиты находится в том же приложении и под тем же OS-пользователем: вредоносный процесс
с его полномочиями, подмена самой защиты, компрометация памяти/ядра или администратор могут
обойти её. Для более сильной границы нужен отдельный OS-пользователь/VM и внешний egress proxy.

При разработке использованы рекомендации
[OWASP по prompt injection](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)
и [OWASP по SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html):
решение модели не заменяет контроль полномочий на стороне инструментов.
