# Skill: code (core, L2)

Обзор и правка КОДОВОЙ БАЗЫ репозитория. Для задач: исправить баг в коде, отредактировать
файлы проекта, найти нужный код, разобраться в репозитории, реализовать фичу, прогнать тесты.

## Когда использовать
- Нужно ИССЛЕДОВАТЬ репозиторий (где лежит логика, какие файлы) и/или ВНОСИТЬ ПРАВКИ в код.
- Исправление багов, реализация изменений, навигация по большому проекту, запуск тестов.

## Когда НЕ использовать
- Обычный веб-поиск/вопрос без работы с кодом — это другой путь (дешевле).

## Инструменты
- `glob_files(pattern, path)` — найти файлы по маске. Read-only.
- `grep_repo(pattern, path, file_glob)` — искать РЕГЭКСП по содержимому рекурсивно. Read-only.
- `list_tree(path, depth)` — дерево каталога. Read-only.
- `read_lines(file_path, start, end)` — прочитать файл с номерами строк. Read-only.
- `edit_file(file_path, old_string, new_string)` — ТОЧЕЧНАЯ правка. Требует подтверждения.
- `run_bash(command, cwd, timeout)` — выполнить shell-команду (тесты). Требует подтверждения; зависит от режима.

## Гранулярность ШАГА (важно для декомпозиции)
Эти инструменты применяются ВНУТРИ одного исполняемого шага, последовательно (найти → прочитать →
поправить → проверить) — НЕ дроби это на отдельные подшаги плана. Простой фикс известного файла
(путь дан) — это ОДИН подшаг. Сложную задачу дроби по СМЫСЛУ (разные участки/фичи), а не по
действиям инструмента.
