# Часть экосистем



## Тезис
Дешёвая модель → высокоспособный агент за счёт ХАРНЕССА, не размера модели.
**Способность = ЦЕЛЬ. Надёжность / скорость / дешевизна = БЮДЖЕТ, в который способность обязана уложиться. НЕ наоборот.**
(Ошибка, которую не повторять: оптимизировать бюджет как цель → задушить исследование/само-расширение.)

## Парадигма (главное)
Агент полезен ВСЕМ не через универсальность, а через **персонализацию**: он оптимизирует САМ СЕБЯ под конкретного пользователя. Универсальность = сумма персонализаций. Код — ИНСТРУМЕНТ, который агент берёт/создаёт, а не фундамент.

## Замкнутый контур = и есть проект (не список модулей, а ОДИН цикл)
```
ВЗАИМОДЕЙСТВИЕ (онбординг-по-исполнению задач Q/A со свободным выбором · подтверждение действий, выбор пунктов в плане, HITL · уточнения)
   ↓ сигнал
IMPLICIT FEEDBACK (что зашло / что отвергнуто — неявно, из реакций)
   ↓ направляет
ПЕРСОНАЛИЗАЦИЯ (память/профиль/роли) + САМО-УЛУЧШЕНИЕ (промпты+few-shots под КЕМ юзер) + САМО-РАСШИРЕНИЕ (добыть способность: навык/MCP)
   ↓ держится компактным через
КОНТЕКСТНЫЙ ИНЖИНИРИНГ (гибридный retrieval — не тащить всё в контекст)
   ↓ под защитой
БЕЗОПАСНОСТЬ/НАДЁЖНОСТЬ (HITL · песочница · не учиться на взломе)
   ↓ → агент лучше ИМЕННО для этого человека → виток повторяется
```

## 4 требования = ОДИН тест тезиса в 4 режимах (НЕ компромисс «выбери 2»)
повседнев · бенчмарки · надёжность · скорость — сильно по всем 4 одновременно = тезис верен.
**НЕ фитимся под GAIA/бенчи — это термометр, не цель.**

## ТРИ РАЗРЫВА контура — ЗАКРЫТЫ ✅ (2026-06-11, 107 тестов)
1. ✅ **Per-user само-улучшение (сердце).** `graph_backward_user`: из неудач юзера + КТО он (профиль) → персональные few-shots виноватых нод (ядро заморожено). Триггер при деградации; CLI `--user <id>`. Доказано живьём.
2. ✅ **Измеримый accept/revert.** `_before_after_eval`: прогон ДО/ПОСЛЕ на кейсах, override сохраняется только при after>before, иначе откат.
3. ✅ **reflexion-обоснованность.** `grounding` + GROUNDING_GATE: reason/fast без базы → deliberate (заземление, не выдумка); порог низкий — без над-эскалации.

## Решения юзера (жёсткие, не нарушать)
- Ядро (системные промпты ключевых нод) ЗАМОРОЖЕНО для backward. Крутятся только few-shots + саб-агенты.
- Персонализация ВНУТРЕННЯЯ: роли никогда не упоминать вслух. Онбординг — по ходу исполнения, не допрос.
- **Поиск ✅ СДЕЛАНО** (web_search._relevant_chunks): trafilatura чистка → чанкинг → BM25S → vector-rerank (OpenRouter emb) → budget. Полную страницу не кормим (живьём 3.6k из ~150k). Fallback: нет bm25s→token-overlap, нет ключа→BM25-only.
- Стэш/Excel/MCP — ПРИМЕРЫ гибкой способности, не цель. Не оверфитить под сценарии.
- Кроссплатформа вкл. смарт-часы: тонкий клиент + мозг на сервере.
- Беречь бюджет OpenRouter (~$15). Дорогие прогоны — только по явному слову.

# Память
1. Локальная (текущее общение, инфа из каких - то баз, используемые тулы, подключеннные MCP, A2A, весь поиск по сути, не важно какой. Какие - то воспоминания из сжатия)
2. Глобальная (персональная инфа, логи, трейсы для улучшения, саммари с фул историей диалога, кэши, GraphRAG/ LightRAG/ AgenticRAG, Current Task / Plan / Цель. Какие - то факты)
3. Временная (то что нужно агенту в RunTime и никак потом не сохранится после сессии)
4. Мой агент сам должен решать что и как использовать, подключать. По сути память сама превращается в своеобразный tool (local-memory tmp-memmory или global-memory должны быть тулами - я хз)

# Архитектура

```
START
 └─ recall            память (эпизоды/факты/выводы/цели/саммари) + implicit feedback + external ctx
 └─ goal              целеполагание: aim + «стоящая» цель + rubric (держится в контексте)
 └─ reflexion         Self-Reflexion Choice: выбор ТИПА мышления по анализу задачи
      ├─ fast      → fast_answer ───────────────────────────────→ reflect → END   (System 1, дёшево)
      ├─ clarify   → fast_answer ───────────────────────────────→ reflect → END   (переспросить)
      ├─ reason    → reason ─────────────────→ validation ──────→ reflect → END   (System 2, без тулов)
      └─ deliberate / heavy → [clarify_gate?] → router → (create_skill | skill_selector)
                       clarify_gate — при средней неоднозначности: батч уточнений
                       (маркеры/открытые) перед исполнением; ответы в реестр уточнений
                       прогона, переиспользуются decompose/step/synthesize; нет ответа
                       → разумное допущение. Догон в шаге: инструмент ask_user.
                       skill_selector → decompose → skill_injection
                          → step_executor⟲ (исполнение+валидация ПО ПУНКТАМ)
                          → synthesize ─→ validation → reflect → END               (deliberate)
                                       └→ review (heavy: сквозной ревью deep-моделью)
                                            ├─ проблемы → fix-подшаги → step_executor⟲ → synthesize → validation
                                            └─ чисто → validation
 reflect              запись эпизода (trajectory), извлечение фактов(+тэги, рёбра),
                      рефлексия, саммари, prune, трекинг деградации, авто-self-learning
```
