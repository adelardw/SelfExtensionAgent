# Campaign 600

Воспроизводимый синтетический прогон через установленный Codex CLI и отдельный
сквозной кейс Flow. Авторизация CLI используется штатно; ключи не извлекаются.
Запуск без `--live` только сохраняет набор и протокол, не вызывает модель.

```sh
.venv/bin/python experiments/campaign600/run.py --output data/eval/my-600
.venv/bin/python experiments/campaign600/run.py --live --output data/eval/my-600
```

Требуются авторизованный `codex`, Docker и образ Python с digest из `sandbox.py`.
Одновременно работают два облачных запроса и не более двух маленьких контейнеров.
Лимиты основного прогона: 8 млн учтённых токенов, 800 запросов, одна попытка
исправления по development-примерам. Это потолки, а не целевой расход. Точную
стоимость подписки CLI стенд не получает: `cost_usd: null`.

## Что именно измеряется

| Слой | Кейсы | Проверка |
| --- | ---: | --- |
| Диалоги | 240 | 24 семейства × 10 контекстов; три последовательных решения роутера, сохранение состояния, адресация, ограничения, отмены, зависимости, дедупликация |
| Структурированные задачи | 160 | 20 семейств × 8 вариантов; точный JSON-ответ; объяснение автоматически не оценивается |
| Код | 160 | 20 семейств × 8 вариантов; функция `solve`, 8 development и 24 закрытых примера, исполнение Python в Docker |
| Мини-проекты | 39 | 13 семейств × 3 варианта; несколько файлов, JSONL CLI, собственные unittest плюс 8 development и 40 закрытых примеров |
| Flow | 1 | Реальный `CodingHarness` с инструментами и проверками; выполнены API- и браузерная приёмки в тестовом контейнере, production-сборка не проверена |

Это **не 600 независимых алгоритмов и не 600 сквозных проектов**. Диалоги используют
`ShadowRouter`, код и мини-проекты — адаптер генерации артефактов. Полный цикл SEA
измеряется отдельно на Flow. Нельзя переносить общий процент на SWE-bench,
Terminal-bench, произвольную разработку или модель 9B. Модель CLI не закреплена по
ID. Батчи видят несколько независимых заданий за один запрос; это снижает накладные
расходы, но не воспроизводит одиночный интерактивный сеанс.

Gold, закрытые примеры и оракулы не передаются модели. В диалогах неправильное
состояние не заменяется эталонным перед следующим сообщением. Временные ответы и
ошибки протокола сохраняются; незапущенный кейс никогда не становится успешным.

## Изоляция и воспроизводимость

Контейнер исполнения кода: без сети, read-only root, непривилегированный UID,
сброшенные capabilities, ограничения CPU/RAM/PID/вывода и времени. Монтируется
только каталог конкретного кандидата; исходники оценщика, домашний каталог и Docker
socket не монтируются. Gold сравнивается с JSONL-выводом снаружи контейнера.

`protocol.json` закрепляет hash набора, шести используемых исходников, конфигурацию
и digest образа. Исходники проверяются перед и после вызовов. Возобновление с
изменённым протоколом отклоняется; используйте новый output-каталог. В каждой
попытке сохраняются запрос, схема транспорта, ответ, JSONL-события CLI и usage.
`results`, `dialogues` и `artifacts` содержат результаты и проверяемые кандидаты.
`result-599.json` намеренно не засчитывает Flow.

## Кейс Flow

Точное задание находится в `product_brief.md`. `run_product.py` — журналированный
эксперимент конкретной кампании 2026-11-07; не запускайте его поверх чужого проекта.
Его целевой каталог — `artifacts/flow-video`, а повторные попытки сохраняют checkpoint.
Прерывания и восстановление после изменений обвязки отражаются отдельно в отчёте.
Они не превращают первоначальную попытку в pass@1. По уточнению пользователя
реализацию продукта выполняет **только харнесс**. Начатая оператором доводка была
полностью удалена, файлы восстановлены побайтно из автономного snapshot. Её код не
используется и не засчитывается. Оператор исправляет обвязку, задаёт критерии и
передаёт наблюдения независимой проверки, но не пишет реализацию продукта.

`product_acceptance.py` — независимые конечные проверки, а не доказательство
отсутствия уязвимостей. Выполняйте их в тестовом образе из `Dockerfile.test`,
монтируя только копию продукта и сам файл приёмки. Не импортируйте сгенерированный
код в процесс, имеющий доступ к секретам рабочего окружения.

Конфигурация CLI основана на локальном `codex --help` и
[официальном руководстве non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).

## Исправления по сквозному прогону

В `review-repair-20261107/` сохранены воспроизведение дефектов и регрессионные логи.
Финальный критик раньше получал лишь 4000 символов первых файлов по алфавиту:
в попытке 8 это были Caddyfile, Dockerfile и начало README. Сервер, клиент и тесты
не попадали в `current_source`. Новый ограниченный пакет распределяет место между
файлами, помечает пропуски и разрешает ссылки только на переданные наблюдения.
Проверяются хеши до/после чтения и после ответа критика; секретные и внешние пути
остаются запрещены. Лимит по умолчанию — 24000 символов, для этого облачного
эксперимента явно задано `--review-source-chars 100000`.

Checkpoint теперь сохраняет ограниченный кэш чтений. При resume восстанавливаются
только фрагменты с совпадающим текущим хешем; старые результаты checks не становятся
действительными автоматически. Watchdog учитывает новые наблюдения и проверки,
а не только запись файлов. Подготовка кандидата ответа отделена от независимого
аудита: она может передать кандидат на проверку без повторного полного чтения,
но отрицательный вердикт критика по-прежнему блокирует завершение.

В попытке 10 критик впервые получил все 14 файлов реализации целиком. Он обнаружил
реальную ошибку `save → hide → /api/saved`: независимые проверки воспроизвели её
для гостя и пользователя. Отдельный диагноз о генераторе `.env` оказался ложным:
на старой копии реальные строки, случайные секреты, 0600, отсутствие побочных
эффектов импорта и отказ перезаписи уже проходили проверку. Это сохранено как
false positive, а не как выполненное исправление продукта.

Адаптер Codex теперь передаёт содержимое сообщений без повторного JSON-кодирования
массива сообщений поверх уже сериализованного пакета. Исходные сообщения по-прежнему
записываются в request.json; `message_transport=role_blocks_v1` отмечает новую форму.
Регрессия различает настоящий перевод строки и буквальный обратный слеш + n.
Старые 599 результатов не пересчитаны и относятся к предыдущей версии адаптера.

Дополнительно воспроизведены и исправлены две причины повторного аудита:
служебные source-снимки больше не вытесняют обычные наблюдения из окна критика
и не меняют ключ кэша проверки сами по себе; конкретное исправление из next_steps
имеет приоритет над общим «завершить продукт». Проверки после изменений остаются
обязательными, но не вытесняют известную незавершённую работу из очереди.

Для браузерной регрессии на Mac добавлен явный флаг эксперимента `--browser-runtime`.
Он разрешает командной песочнице читать только установленные каталоги
`chromium[-_…]-<revision>` Playwright, исключая ссылки и профили пользователя.
Флаг выключен по умолчанию в харнессе; сеть и записи за пределами разрешённой
рабочей области остаются закрыты. Проверены реальные запреты чтения профиля,
записи в browser runtime и открытия сетевого сокета, а также запуск Chromium
с локальным HTML в той же песочнице. Это устраняет наблюдавшийся ложный симптом
«icudtl.dat not found», не отключая sandbox. Эксперимент также включает существующий
ограниченный ResultMemory, чтобы результаты проверок окружения не выпадали из
контекста после нескольких чтений; общий production default не менялся.
